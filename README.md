# Детсад-Склад

Программа учёта для детского сада. Сейчас умеет оформлять заявки на поставку товара; дальше будет развиваться (склад, остатки).

## Скачать

Скачайте `DetsadSklad.exe` на [странице релизов](https://github.com/nikartom/detsadsklad/releases/latest) и запустите. Установка не требуется: .NET Framework 4.5+ уже есть в Windows 8, 10 и 11. Для Windows 7 нужен установленный .NET Framework 4.5 или новее.

У файла нет цифровой подписи, поэтому Windows может показать предупреждение: нажмите «Подробнее» → «Выполнить в любом случае».

При первом запуске программа пустая. Заполните страницу «Настройки», затем добавьте поставщика с контрактом и продукты.

## Контракты и продукты

- У поставщика может быть несколько контрактов на разные группы продуктов. У каждого контракта графа «Что поставляет»: «Бакалея», «Заморозка», «Молочная продукция».
- У продукта есть категория — то же слово, что в графе «Что поставляет». В заявке по контракту «Бакалея» предлагаются продукты с категорией «Бакалея» и продукты без категории.
- Продукты привязаны к поставщику и категории, а не к номеру контракта. Когда срок контракта закончится, он появится в разделе «Срок закончился» с кнопкой «Продлить»: остаётся вписать новый номер и дату, продукты прежние.
- Новую заявку можно оформить только по действующему контракту и с датой поставки в его срок.
- **Загрузить контракт из файла** (страница «Поставщики»): выберите PDF контракта. Программа сама заполнит поставщика (название, ИНН, адрес, почту, телефон), контракт (номер, что поставляет, даты) и продукты из спецификации с ценами. Перед сохранением всё видно на экране; если сумма позиций не совпала с ценой контракта, программа предупредит. Поставщик, который уже есть, узнаётся по ИНН: к нему добавляется новый контракт, а у его продуктов обновляются цены.

## Какие контракты понимает программа

Контракты разных площадок устроены по-разному, поэтому для каждой площадки в программе свой профиль распознавания. Сейчас поддерживается:

| Площадка | Что читается |
|---|---|
| КУЗБАСС TRADE (подпись «РТС-тендер») | номер и предмет контракта, дата заключения, срок поставки, поставщик из раздела реквизитов, спецификация |

Контракт другой площадки программа не будет разбирать наугад: она сообщит, что такой вид пока не поддерживается, и поставщика можно завести вручную.

**Хотите, чтобы программа понимала ваши контракты?** Свяжитесь с автором: создайте обращение на странице [Issues](https://github.com/nikartom/detsadsklad/issues) и опишите, с какой площадки ваши контракты. Пример контракта пришлите только по договорённости и без реальных реквизитов — сами файлы в открытый доступ не выкладываются.

## Где лежат данные

| Что | Где |
|---|---|
| Всё (по умолчанию) | `Документы\ДетсадСклад\` |
| Для работы с флешки | создайте рядом с exe пустую папку `Данные программы` — данные будут в ней |
| Заявки, справочники | `data.xml` |
| Резервные копии | `Копии\` (по одной в день, хранятся 30 последних) |
| Файлы Word | `Заявки\Поставщик\Контракт\Заявка №7 от 30.10.2026.docx` |

Чтобы перенести на другой компьютер, скопируйте эту папку целиком. Одновременно с папкой может работать только одна копия программы.

## Начальные данные

В репозитории нет реальных реквизитов. Собранная из него программа стартует пустой: всё заполняется в настройках и справочниках.

Чтобы программа сразу запускалась с данными конкретного садика, положите их при сборке в `src/DetsadSklad/Assets/InitialData.local.xml` (это обычный `data.xml`, файл не хранится в git). Они окажутся внутри exe, поэтому такой exe нельзя выкладывать в открытый доступ.

## Сборка

Нужен MSBuild (Visual Studio или Build Tools 2022). .NET SDK не нужен.

```bash
pwsh -File build.ps1
```

Скрипт при необходимости скачает справочные сборки .NET 4.5 в `.tools`, соберёт программу, прогонит проверки и положит exe в `dist`.

## Устройство

- `src/DetsadSklad` — WPF, .NET Framework 4.5, без сторонних библиотек.
  - `Models` — данные. Заявка хранит копию реквизитов: старые документы не меняются, если изменился адрес или цена.
  - `Services` — хранение (`DataStore`), правила заявок (`RequestLogic`), сборка Word (`RequestDocumentBuilder`).
  - `Services/Pdf` — чтение текста и линий таблиц из PDF; `Services/ContractProfiles` — профили площадок. Новая площадка: класс с `IContractProfile` и строка в `ContractPdfReader.Profiles`.
  - `ViewModels`, `Views`, `Themes` — экраны и оформление. Новый раздел: модель экрана, `UserControl`, `DataTemplate` и кнопка в `MainWindow.xaml`.
  - `Assets/ZayavkaTemplate.docx` — шаблон документа с полями вида `{{OrgName}}`; можно править в Word.
- `tests/DetsadSklad.Tests` — проверки логики и открытия всех экранов, запускаются из `build.ps1`. Если задать переменную окружения `DETSAD_SCREENSHOTS` (путь к папке), проверка сохранит туда снимки экранов на тестовых данных.
  Чтобы заодно проверить чтение своих контрактов, задайте `DETSAD_CONTRACTS` — папку с PDF. Сами контракты в репозиторий не кладутся: в проверках используется выдуманный контракт.
- Новое поле в данных: добавьте свойство с `[DataMember]`, старый `data.xml` прочитается без него.
